## 1. نظرة عامة

**أكاديمية أُلفة** منصة تعليمية أونلاين متكاملة لتحفيظ القرآن الكريم وتجويده وعلومه، موجهة للأطفال واليافعين (من عمر 4 سنوات فما فوق). المنصة ليست موقعاً تعريفياً فقط، بل نظام تشغيل كامل للأكاديمية يربط بين:

- **ولي الأمر** (تسجيل، متابعة، دفع)
- **الطالب** (حصص، حفظ، واجبات)
- **المعلم/المعلمة** (تدريس، تقييم، تقارير)
- **الإدارة** (تشغيل، جدولة، مالية)

**الرسالة التسويقية:** "نزرع القرآن في القلوب، ونرافق أبناءكم في رحلة الإيمان والعلم."

**الشعار:** أكاديمية أُلفة — *لتحفيظ القرآن الكريم وتجويده وعلومه*
(⚠️ تصحيح لغوي مطلوب على ملف الشعار الحالي: "لتحفيض" ← "لتحفيظ"، و"القران" ← "القرآن")

**الهوية اللونية:**

| Gold | `#C9A227` |

## 2. أهداف المشروع

1. توفير تجربة تسجيل وتقييم سلسة لولي الأمر قبل انضمام الطفل لأي حلقة.
2. إعطاء ولي الأمر رؤية واضحة ومستمرة لتقدم طفله (حفظ، مراجعة، حضور، تجويد).
3. تمكين المعلم من إدارة حلقاته وتقييم طلابه ورفع تقارير أسبوعية دون احتكاك.
4. إعطاء الإدارة أدوات تشغيلية كاملة: جدولة، حلقات، اشتراكات، تقارير.
5. بناء نظام قابل للتوسّع تدريجياً (MVP أولاً ثم مزايا متقدمة) بدل محاولة بناء كل شيء دفعة واحدة.

### مؤشرات نجاح أولية (تُحدد أرقامها لاحقاً مع الإدارة)
- نسبة إتمام رحلة التسجيل (Registration → Assessment → Enrolled).
- نسبة الحضور الأسبوعي.
- نسبة إرسال التقارير الأسبوعية في وقتها.
- معدل تجديد الاشتراك (Retention).

## 3. الأدوار (Roles) والشخصيات

| الدور | الوصف المختصر |
|---|---|
| `super_admin` | صلاحية كاملة على النظام، تُمنح لمالك/مدير الأكاديمية. |
| `admin` | تشغيل يومي: طلاب، معلمون، حلقات، جدولة، تقارير، مدفوعات. |
| `teacher` | يدير حلقاته فقط: حضور، تقييم، حفظ، واجبات، تقارير. |
| `parent` | يدير أبناءه المسجَّلين فقط: متابعة، حصص، دفع. |
| `student` | حساب اختياري لليافعين (13+) لعرض تقدمهم ومهامهم مباشرة. |

أدوار مستقبلية (V2): `support`, `accountant`, `content_manager` — مضافة في الـ enum من الآن لتفادي migration مكلف لاحقاً، لكن بدون شاشات مخصصة في MVP.

تفاصيل الصلاحيات الكاملة موجودة في [`database-schema.md`](./database-schema.md#6-مصفوفة-الصلاحيات).

## 4. رحلة المستخدم الأساسية (End-to-End)

```
الموقع العام → "احجز تقييم" → بيانات الطفل → موعد تقييم
→ تقييم المعلم → مستوى مقترح (Level) → اختيار البرنامج/الجدول
→ الاشتراك والدفع → حساب ولي الأمر جاهز
→ [حلقة أسبوعية] حصة مباشرة → حضور → تقييم → حفظ/مراجعة → واجب
→ تقرير أسبوعي لولي الأمر → إشعار → استمرار/تجديد الاشتراك
```

هذه الرحلة هي العمود الفقري لتصميم الـ Database والـ RLS: كل بيانات الطالب (حفظ، حضور، تقييم) تتغذى من **جلسة حصة واحدة (`class_sessions`)**، وتتجمّع أسبوعياً في **`weekly_reports`**.

## 5. نطاق النسخة الأولى (MVP) مقابل V2

### MVP — الإطلاق الفعلي
- **عام:** الرئيسية، من نحن، البرامج، المعلمون، الأسئلة الشائعة، تواصل، حجز تقييم، عربي/إنجليزي.
- **ولي الأمر:** حساب، أبناء متعددون، جدول، دخول الحصة (رابط خارجي Zoom/Meet)، حضور، تقدم القرآن، تقارير أسبوعية، إشعارات أساسية.
- **معلم:** لوحة تحكم، حلقاتي، طلابي، تسجيل حضور، تقييم حصة، تسجيل حفظ/مراجعة، واجب بسيط، توليد تقرير أسبوعي.
- **إدارة:** طلاب، أولياء أمور، معلمون، حلقات (يدوي)، برامج ومستويات، جدولة الحصص، عرض التقارير، اشتراكات ومدفوعات (تسجيل يدوي في البداية إن لم تُحسم بوابة الدفع بعد).

### V2 — بعد إثبات الجدوى
- قارئ قرآن تفاعلي + صوت.
- نظام Gamification كامل (XP، شارات، مستويات).
- شهادات PDF + QR verification.
- نظام رسائل موسّع + إشعارات WhatsApp.
- تحليلات متقدمة للإدارة وأداء المعلمين.
- غرفة بث مباشر مبنية داخلياً (WebRTC) بدل الاعتماد على Zoom/Meet.
- تطبيق جوال (باستخدام نفس الـ Backend).

## 6. البرامج التعليمية (Seed Data منطقي)

| البرنامج | الفئة العمرية | المحتوى |
|---|---|---|
| تأسيس القرآن | 4–6 | قصار السور، تلقين، مخارج الحروف، آداب إسلامية |
| تحفيظ القرآن | 6–12 | حفظ جديد، مراجعة، تسميع، تجويد أساسي |
| القرآن والتجويد | 8–15 | حفظ + أحكام تجويد متقدمة + مخارج + وقف وابتداء |
| القرآن والعلوم الإسلامية | يافعون | قرآن، حديث، سيرة، عقيدة، فقه، أخلاق |

كل برنامج يحتوي مستويات (`levels`): A (مبتدئ) → B (قارئ) → C (حافظ جزئياً) → D (متقدم)، تُحدَّد تلقائياً كتوصية من نظام التقييم الأولي ثم تعتمدها الإدارة.

## 7. المتطلبات غير الوظيفية (Non-Functional Requirements)

- **الأمن والخصوصية أولوية قصوى** (مستخدمون أطفال): عزل بيانات كل طرف عبر Row Level Security — لا واجهة أمامية تصل لبيانات طفل لا يخصّها. راجع [`database-schema.md`](./database-schema.md#5-سياسات-الأمان-row-level-security).
- **اللغات:** عربي (RTL) و إنجليزي (LTR) من اليوم الأول، مع بنية جاهزة لإضافة الفرنسية لاحقاً.
- **الاستجابة:** تصميم متجاوب بالكامل (الأهل غالباً يستخدمون الجوال).
- **التوفر:** الحصص المباشرة تعتمد أولاً على مزوّد خارجي (Zoom/Google Meet) لتقليل نقاط الفشل في MVP.
- **قابلية التوسع:** بنية البيانات تدعم إضافة أدوار/برامج/عملات جديدة دون إعادة هيكلة كبرى.

## 10. قرارات مفتوحة (يجب حسمها قبل/أثناء المرحلة 6)

هذه نقاط لا يمكن افتراضها بشكل تعسفي لأنها تعتمد على قرار عمل حقيقي من صاحب الأكاديمية:

1. **بوابة الدفع والعملة:** تعتمد على الدولة/الدول المستهدفة (مثلاً Stripe لو الجمهور دولي، أو بوابة محلية لو السوق مغربي/خليجي تحديداً).
2. **أسعار البرامج والخطط** (Basic/Standard/Premium) — غير محددة بعد.
3. **مزوّد الفيديو النهائي لـ MVP:** Zoom أم Google Meet (يؤثر على شكل `meeting_url` وتكامل الجدولة).
4. **مزوّد البريد الإلكتروني/الإشعارات** (Resend, SendGrid, إلخ) وسياسة WhatsApp لاحقاً.
5. **المنطقة الزمنية الافتراضية للأكاديمية** (تم وضع placeholder `UTC` في قاعدة البيانات، انظر `group_schedule_slots.timezone`).

> هذه النقاط مُعلَّمة صراحة في السكيما (SQL) بقيم افتراضية محايدة قابلة للتغيير، وليست قراراً نهائياً من طرفي.
